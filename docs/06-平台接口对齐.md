# 06 · 本体引擎 ↔ robot-dispatch 平台接口对齐

> 平台（robot-dispatch-server，Go/Gin，`/api/v1/*`，端口 8090）已有完整 REST API。
> 本文把平台已有契约**吸收进本体工程**：目录、鉴权模式、本体→平台映射、遥测桥接，
> 以及本体引擎应新增的 internal 端点（对齐平台风格，不发明平行协议）。

## 1. 平台 REST API 目录（已查实）

**机器间内部端点**（`X-Internal-Token` 请求头，常量时间比对 `telemetry.token`，不走登录态）：

| 端点 | 用途 |
|---|---|
| `POST /api/v1/internal/telemetry` | 设备/网关遥测上报 |
| `POST /api/v1/internal/voice-logs` | 语音记录上报 |
| `POST /api/v1/internal/robot-chat` | 机器人语音对话 |

**登录态用户端点**（JWT + RBAC 权限码）：
- 账户：`auth` / `users` / `roles` / `permissions`
- 台账：`sites` / `projects` / `customers` / `contracts` / `centers`
- 任务工单：`tasks`（+`POST /tasks/:id/actions`）/ `tickets`
- 机器人：`robots/*` —— 台账 CRUD、`components/connections/actions/cameras/commands`、`face/*`(8)、`voice/*`、`huilun/*`
- 知识：`kb/*`、`chat/*`；运维：`events/stream`(SSE)、`system-logs`、`overview/metrics`、`map/sites`、`analytics`

## 2. 鉴权模式（本体引擎照抄）

- **内部端点**：`X-Internal-Token` 头，`subtle.ConstantTimeCompare` 比对 `telemetry.token`（配置）；未配置时返回 503。
- **用户端点**：`Authorization: Bearer <JWT>` + `RequirePermission("权限码")`。

## 3. 平台关键契约（字段级，已从源码摘录）

**遥测 `TelemetryPayload`**（`internal/handler/telemetry.go`，字段全可选、缺省不覆盖库值）：

```
robot_id, battery(int), status, temp, signal, area, task,
ti5(string, Ti5 遥测 JSON 原文·网关透传), charging, ip, wifi_ssid,
app_version, sn, map_name, located, pos_x/y/theta, odometer,
today_km, today_min, cur_speed, estop
```

**机器人 `Robot` 模型**（`internal/model/national.go`）：台账字段（id/name/model/form/scene/project_id/city/status/battery/task/area/owner…）+ 遥测扩展（charging/wifi_ssid/sn/device_mac/map_name/located/pos…）+ 控制字段（enabled/mode/speed_limit/cur_speed/odometer/estop/takeover_by/ip/link/fw…）+ `ti5`（人形机器人遥测 JSON 文本）+ `gateway_url`（真机接入网关）。

## 4. 本体 → 平台映射

| 本体（embodied-ontology） | 平台（robot-dispatch） | 说明 |
|---|---|---|
| Robot.id / serial / model / status / firmware_version | Robot.SN / model / status / fw | 直接对应 |
| Robot.current_battery（动态属性） | TelemetryPayload.battery / Robot.battery | 经时序绑定物化 |
| BodyPart | RobotComponent（`robot_component.go`，RobotID+Key 联合唯一） | 部件树 ↔ 组件表 |
| Capability | **平台无对应列** | 需靠能力视图（docs/05）新增 |
| Task（具身：requires_capability/verdict） | Task（业务：project_id/progress） | 语义不同，需映射层 |
| TelemetryMetric（细粒度测点） | TelemetryPayload.ti5（JSON 原文透传） | 见 §5 桥接 |
| ActionLog | 平台 oplog / 无本体动作审计 | 需新增 |

**关键结论**：平台的 `ti5` 字段是现成的「细粒度数据搭车通道」——本体把 (entity, metric) 时序打包成 JSON 塞进 `ti5`，**平台零改动**即可接收本体的 force_reading/joint_angle 等测点。

## 5. 遥测桥接（本体 → 平台 TelemetryPayload）

`eo/platform.py::build_platform_telemetry(store, telemetry, bindings, robot_id)`：

```
flat 字段 ← 本体机器人台账 + 动态属性（battery 经绑定物化）
ti5 字段 ← 本体细粒度测点打包：
  {"ontology_version":"1.1.0",
   "metrics":{"eo:part/ti5/six-axis-force":{"force_reading":4.0},
              "eo:part/ti5/wrist":{"joint_angle":32.0},
              "eo:robot/ti5":{"battery":86.0}}}
```

平台侧 `POST /internal/telemetry` 原样入库，`ti5` 字段透传保留，后续可解包到本体时序库/分析。

## 6. 本体引擎应新增的 internal 端点（对齐平台风格）

| 端点 | 用途 | 鉴权 |
|---|---|---|
| `POST /internal/ontology/capability-view` | 引擎主动推送能力视图（或平台拉取 `GET`） | X-Internal-Token |
| `POST /internal/ontology/entities` | 平台写本体实体（Gate A） | X-Internal-Token |
| `POST /internal/ontology/tasks/{id}/dispatch` | 下发本体任务（Gate B + 动作） | X-Internal-Token |
| `POST /internal/ontology/telemetry` | 本体细粒度遥测上报（对齐 §5 桥接） | X-Internal-Token |
